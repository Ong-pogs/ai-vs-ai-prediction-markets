Build me a local harness that lets several AIs compete at paper trading on Polymarket and Kalshi through the Predictefy API. Every AI gets the same data, the same question and the same $100 of paper money. The harness places the paper orders, keeps each AI's books, settles the bets from the real results, and shows it all on a local dashboard. It must never place a real order and never ask for a venue key or a wallet.

STACK
- Node.js 22.12 or newer, ES modules, no npm dependencies. Use the built-in http server, fetch, child_process and node:test.
- Files: src/cli.mjs (commands), src/config.mjs, src/predictefy.mjs (API client), src/markets/sportsScreen.mjs, src/facts.mjs, src/prompt.mjs, src/rules.mjs, src/contestants/ (one file per kind), src/execution/paper.mjs, src/settle.mjs, src/ledger.mjs, src/store.mjs, src/runner.mjs, src/server.mjs, src/dashboard/index.html, test/*.test.mjs, config/*.json, .env.example, README.md.
- Read keys from a local .env file with node:util parseEnv. Never copy them into process.env, never log them, never write them to a run folder, never pass them to a child process. Treat the placeholder in .env.example as "not set" and stop with a clear message. If the ARENA_ENV_FILE environment variable is set, read the keys from that file instead.
- Bind the dashboard to 127.0.0.1 only, default port 8815.

CONFIG (one JSON file describes a run; a new line-up must be a config change, not a code change)
- name, title, startingCash (100), stakeUsd (5), betsPerRound {min, max} (2 and 2), intervalMinutes (30), durationHours (24), answerDeadlineSec (150), maxMarketsPerRound (8), settleGraceHours (3), dashboardPort, facts.fairPrice (false), execution {mode "predictefy-paper", slippage 0.02, fillWaitSec 90, pollEverySec 2}.
- markets: a list of sources. Build the kind "sports-screen" with marketType, venues, kickoffFromHours (-3), kickoffToHours (1.5), priceMin (0.05), priceMax (0.95), minSizeAtPrice (100), maxPerSport (3), maxQuoteAgeSec (60).
- contestants: a list, each with name, label, kind and that kind's settings. Kinds:
  - claude-cli (model, effort): run `claude -p --model <model> --effort <effort> --output-format json --tools "" --no-session-persistence --disable-slash-commands --strict-mcp-config --setting-sources "" --system-prompt "<one line>"` with the prompt on stdin, in an empty working folder. Read the answer from the JSON's result field, the model names from modelUsage, the cost from total_cost_usd.
  - codex-cli (model, effort, codexHome): run `codex exec -m <model> -c model_reasoning_effort="<effort>" -c web_search="disabled" --disable shell_tool -s read-only --skip-git-repo-check --ephemeral --color never -C <empty folder> --output-schema <schema file> -o <answer file> -` with the prompt on stdin. Read the model and "tokens used" from the header Codex prints on stderr.
  - jev (model, pinned to jev-1.13.0): POST https://api.typesafe.ai/v1/systemone with Authorization: Bearer TYPESAFE_API_KEY and a body of state, model and questions. One request per market, all in parallel.
  - openai-chat (baseUrl, model, keyName): POST {baseUrl}/chat/completions with a system and a user message and response_format json_object. The key is read from .env by keyName.
  - random (seed): not an AI. Seeded picks, as a baseline.
- Start every command-line AI with windowsHide, with a hard deadline that kills the process tree, and with an environment stripped of agent-session variables (CLAUDECODE, CLAUDE_CODE_*) and of the harness's own keys.

DATA (base URL https://data.predictefy.com, key in the Authorization: Bearer header)
- Games: GET /v1/sports/screen?marketType=moneyline&from=<ISO>&to=<ISO>&limit=200, paged with page.nextCursor, 5 credits a page. Each row has the teams, kickoffAt, status and a market with two selections. Each selection has cells, one per venue, with marketId, outcomeId, gross and net probability (the ask, before and after fees), sizeAtPrice, asOf, stale and source, plus Predictefy's own no-vig fair probability.
- A cell can be traded only if source is "live", stale is false, the venue is one of the configured venues, the price is in range, the quote is recent, and sizeAtPrice is at least four times the order (the paper engine fills at most a quarter of a displayed lot per book update). Anything else is refused by the paper engine with 409 PAPER_NO_LIVE_BOOK, so never offer it. A game needs a tradable cell on both sides.
- Paper orders: POST /v1/paper/orders with an Idempotency-Key header and a body of venue, marketId, outcomeId, side "buy", price (a limit on the cent grid), size (shares) and tif "IOC". Then GET /v1/paper/orders/{id} until the status is no longer open or partially_filled; if it still is after fillWaitSec, POST /v1/paper/orders/{id}/cancel and read it once more. The order carries filledSize, avgFillPrice, feesPaid and fills. Paper trading costs 0 credits. Never call the account reset route.
- Results: GET /api/{venue}/fetchMarket?marketId=..., 1 credit. Predictefy's paper engine does not settle Polymarket or Kalshi positions, so the harness settles its own books.
- Count the x-credits-charged response header by endpoint. Retry 429 and 5xx with a short backoff; honour Retry-After.

A ROUND
1. Settle: read the market of every open bet. A bet is won or lost only when the market's status is "resolved" AND the price of the held outcome is 0.985 or more (won, pays $1 a share) or 0.015 or less (lost). A resolved market can still carry an old in-game price; that is never a result. Otherwise the bet stays open, valued at the catalogue price.
2. Slate: from the sports screen, take games in the kickoff window. Never offer a game any contestant already holds. Order: games not asked before, games yet to start, games on more venues, preferred competitions, soonest kickoff. Cap each sport and the total.
3. Facts: for each game, short plain sentences with every calculation already done: the game, when it starts or how long ago it started, what YES and NO mean, and the price of each side on each venue. Show Predictefy's fair price and how each side compares with it only when facts.fairPrice is true; always save it with the game.
4. Ask every contestant at once, with the same facts. For each game they give: call (BUY_YES, BUY_NO or SKIP: what they would do by choice), p_yes (0 to 1), lean (YES or NO), strength (0 to 100) and, for text models, a one-sentence reason. Text models get one prompt with every game and answer in JSON; cut the reply from the first { to the last } before parsing and validate every field. For Jev ask three typed questions per game: a choice of BUY_YES, BUY_NO or SKIP, a noul for "YES wins", and a choice of YES or NO for the side to hold; its strength is 100 x (1 - its probability of SKIP).
5. A late, invalid or failed answer is a skip for that round and is recorded with its reason. Keep the error text of a failed call. When it names a plan or rate limit, a missing credit, an expired login or a service error (HTTP 429, 402, 401, 5xx and the like), that is not the AI's doing: show the contestant as unavailable for that round, not as failed.
6. Bet by one fixed rule, the same for everyone. When betsPerRound.min is above zero, rank every game by strength (ties to the game shown first), on the side called or, for a skip, the side leaned to, and bet down that list until max bets have filled. When min is zero, bet only the BUY calls. Each bet: floor(stake / net price) shares, limit = quoted ask plus slippage rounded up to the cent and capped at 0.99, on the venue with the lowest price after fees; try the next venue only on PAPER_NO_LIVE_BOOK or an order that filled nothing. A bet is the full stake or nothing: with less than one stake of free cash, no order is sent.
7. Every order's Idempotency-Key is ai-vs-ai-<run id>-<contestant>-r<round>-<game id>-<side>-<venue>. Save the intent to disk before sending, and on restart replay the same key so an order in flight is recovered, never placed twice.
8. Record what each contestant wanted (buy or skip) for every game, separately from what the rule made it bet.

STATE AND COMMANDS
- Each run has its own folder runs/<run id>/ with state.json (written atomically after every step), events.jsonl (every prompt, answer, order, fill and settlement), rounds/rNNN.json, harness.log and run.pid.
- Rounds run on a fixed schedule from the start time. On restart the run resumes from state; a round whose time passed while it was down is recorded as missed.
- When the run ends, settle once more, write run-finished.json with every contestant's final numbers, keep folding in late settlements for settleGraceHours, then exit. Bets still open are valued at the last catalogue price and listed as unsettled.
- Commands: start (resume or create; --start-at HH:MM, --run-id, --rounds, --interval-min, --new), launch (the same as a detached background process), status, stop (a STOP file the run notices within 15 seconds), settle, dashboard, check (ask every contestant one sample question), compare (read the saved run and print each contestant's bets and profit over every round, and over only the rounds in which every AI answered, with each round a contestant sat out and why; --save writes it to the run folder).
- One contestant's failure must never stop a round, and one round's failure must never stop the run.

DASHBOARD (dark, large type, readable on a screen recording, one file, no libraries)
- Header: the title, the rule in one sentence, round N of M, a countdown to the next round.
- A card per contestant, ranked by balance: balance, profit, bets won, lost and open, how often it would have skipped by choice, how fast it answers. The random picker is styled as a baseline.
- One line chart of balance after every round: one y axis in dollars, 2px lines, an end dot and a direct label on each line, a legend, a crosshair with one tooltip listing every contestant. The baseline is a grey dotted line.
- Tabs: this round (every game with its prices, the hidden fair price, and each contestant's call, odds, reason and bet), every bet (with how it settled and which endpoint said so), rules and data (the rule, the same comparison the compare command prints, where each number comes from, credits by endpoint, each AI's calls, tokens and cost).
- On a card, count the rounds a contestant was unavailable apart from its failed answers, and average its answer time over the rounds it answered.
- Say on the page that paper results are not real results. Name the endpoint behind each number. Insert every string from an API or a model with textContent, never innerHTML.
- If Predictefy answers 402 or PLAN_REQUIRED, show it with a link to the plans.

ALSO
- Unit tests with no network: the answer parser (clean, fenced, missing and malformed answers), the betting rule, the facts built from saved sports-screen rows, the settlement reader (resolved and decisive, resolved but not decisive, not resolved), the comparison over every round and over the rounds every AI answered (with one unavailable and one late round), the paper order flow against a stand-in engine (fill, wait and fill, no live book on one venue, never fills and is cancelled, no cash, replay of the same key), each contestant kind against a stand-in command line or a local fake server (including a slow answer that is killed at the deadline), and one whole run that stops and resumes.
- README with quick start, what a round does and which endpoint each step uses, the contestant kinds, the rule, the settings, what it costs to run, and a plain list of what it cannot tell you.
